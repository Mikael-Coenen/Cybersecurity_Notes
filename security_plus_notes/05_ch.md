# Vulnerability Management
- Vulnerability management: identifying, prioritizing, and remediating vulnerabilities in our environments
- Vulnerability scanning: detect new vulnerabilites as they arise and implement a remediation workflow that addresses the highest-priority vulnerabilities

## Identifying Scan Targets
- Steps:
    - Determine if any regulatory requirements apply to the scans
    - Identify the systems that will be covered by the scan (data classification of the system, system exposed to internet, what services offered)
    - Build an asset inventory of tools on the network
    - Determine asset criticality
## Determining Scan Frequency
- Cybersecurity professionals use automated scanning tools
- Factors that determine frequency of vulnerability scans:
    - Risk appetite: an organizations willingness to tolerate risk within the environment
    - Regulatory requirements: may dictate a minimum frequency for scans
    - Technical constraints: may limit the frequency of scanning (system might be only able to scan X amount of times per day)
    - Business constraints: avoid disruption during periods of high business activity with resource-intensive scans
    - Licensing limitations: may curtail the bandwidth consumed by the scanner or # of scans
## Scan sensitiviy levels
- Configuration settings determine what types of checks the scanner will perform and should be customized to achieve its objectives without disrupting the target environment
- Disabling unnecesary plug-ins improves the speed of the scan
## Supplementing network scans
- Vulnerability scans that run over a network has the possibility of showing false positives
- To fix this problem you should supplement your remote scans with info about server configurations:
    - Credentialed scans: provide scanners with credentials that allow the scanner to receive config info about the target server
    - Agent-based scanning: small software agents are installed on each target server and they report info back to vulnerability platform for analysis
## Scan perspective
- Scan perspectives: conduct scans from different locations on the network providing a different view into vulnerabilities
## Scanner maintenance
- Admin should conduct regular maintenance of their vulnerability scanner to ensure the scanning software and vulnerability feeds remain up-to-date
## Scanner software
- Regular patching of scanner software protects an organization from scanner-specific vulnerabilities
## Vulnerability Plug-in Feeds
- Scanners should be configured to retrieve new plug-ins on a regular basis
## Security Content Automation Protocol (SCAP)
- SCAP: standardized approach for communicating security-related info, led by NIST
    - Common Configuation Enumeration (CCE): provides a standard nomenclature for discussing system configuration issues
    - Common Platform Enumeration (CPE): provides a standard nomenclature for describing prodcut names and versions
    - Common Vulnerabilities and Exposures (CVE): provides a standard nomenclature for describing security-related software flaws
    - Common Vulnerability Scoring System (CVSS): provides a standard approach for measuring and describing the severity of security-related software flaws
    - Extensible Configuration Checklist Description Format (XCCDF): a language for specifying checklists and reporting checklist results
    - Open Vulnerability and Assessment Language (OVAL): a language for specifying low-level testing procedures used by checklists
## Vulnerability Scanning Tools
- Infrastructure vulnerability scanning
    - probes network-connected devices for known vulnerabilities
    - Attempts to determine type of device and its configuration
    - Common network scanner on the market: Nessus, Qualys, Rapid7, OpenVAS
- Application testing:
    - Analyze custom developed software
    - Commonly used as part of the software development process
    - Uses three techniques:
      - Static testing: analyzes code w/o executing it
      - Dynamic testing: executes code as part of the test
      - Interactive testing: combines static and dynamic testing
- Web application scanning:
    - Analyze security of web applications
    - Combines network scans of web servers with probing of web applications
    - Nikto and Aracni are some open-source scanners
## CVSS
- CVSS: Common Vulnerability Scoring System, assesses the severity of security vulnerabilities on a scale from 0 to 10
- Vulnerability is rated on 8 different measures, first 4 are the exploitability, last three are impact, 8th is scope
### CVSS Measures:
Exploitability
- Attack vector metric (AV): describes how an attacker would exploit the vulnerability
- Attack complexity metric (AC): describes the difficulty of exploiting the vulnerbility
- Privileges required metric (PR): describes type of account access an attacker would need to exploit a vulnerability
- User interaction metric (UI): describes whether the attacker needs to involve another human in the attack
Impact
- Confidentiality metric (C): describes type of info disclosure that might occur
- Integrity metric (I): describes type of info alteration that might occur
- Availability metric (A): describes type of discruption that might occur
Scope
- Scope metric (S): describes whether the vulnerability can affect system components beyond the scope of the vulnerability
## Interpreting the CVSS Vector
- CVSS vector uses a single line to convey the ratings of a vulnerability on all 8 metrics
- CVSS base score: single number representing overall risk posed by a vulnerability
## Confirmation of Scan Results
- Positive report: when a scanner reports a vulnerability (if accurate its true, inaccurate false)
- Negative report: when a scanner reports a vulnerability is not present (if accurate its true, inaccurate false)
## Other Data Sources
- Besides the scanner(s) turn to other sources of info for analysis:
    - Log reviews
    - Security Information and Event Management (SIEM) systems
    - Configuration management systems

# Vulnerability Classification

## Patch Managment
- When a system on a network is running an outdated version of an OS or application and therefore requires a security patch
## Legacy Platforms
- When a system on a network is running a discontinued software and therefore requires an upgrade or change of software
- If those options are not possible its best to try to isolate the system as much as possible and not connect it to a network
## Weak Configurations
- Weak configurations settings on systems, applications, and devices
- Can include: use of default settings, using default credentials or unsecured accounts, open service ports, open permissions
## Error Messages
- Debug modes being enabled can give attackers info about the structure of a database
- Solution is to disable debug modes on systems with public exposure
## Insecure Protocols
- When a system is using an old protocol from early internet days that did not have security in mind
- Ex: old protocols failed to use encryption to protect usernames, passwords, etc
## Weak Encryption
- Two importants choices when implementing encryption: what algorithm to use, what encryption key to use with that algorithm

# Penetration Testing
- Authorized, legal attempts to defeat an organizations security controls

## Adopting Hacker Mindset
- Instead of trying to defend against all possible threats, pen testers need to only find one vulnerability to exploit
## Benefits of Pen testing
- Pen testers provide us with knowledge we can't obtain elsewhere
- Pen testers provide a blueprint for remediation
- Pen testers provide us w/ essential info on specific attack targets
Side note: threat hunting is when a person looks for signs of an attack and remediates the system
## Penetration Test Types
Categories
- Physical: identifying and exploiting vulnerabilities in an organizations physical security controls
- Offensive: security professionals act as attackers to identify and exploit vulnerabilities in an organizations networks, systems, and applications
- Defensive: evaluate an organizations ability to defend against cyberattacks
- Integrated: combines aspects of offensive and defensive to provide a comprehensive assessment of an organizations security posture

Classifications for how much knowledge testers know about the environment

- Known environment: tests performed with full knowledge of the underlying technology, configs, settings
- Unknown environment: intended to replicate what an attacker would encounter
- Partially known environment: blend of known and unknown
## Rules of Engagement (RoE)
- Timeline for the engagement and when testing can be conducted
- What locations, systems, applications, or other potential targets are included or excluded
- Data handling requirements
- What behaviors to expect from the target (if some limit pen testers ability to do tests this can be a waste of time)
- What resources are committed to the test
- Legal concerns
- When and how communications will occur
## Reconnaissance
- Pen tests begin with a reconnaissance phase, seeking to gather as much info as possible
- Passive reconnaissance: seek to gather info without directly engaging with target
- Active reconnaissance: directly engage the target in intelligence gathering
- War driving: tester drives by facility w/ antennas to try to eavesdrop on wireless networks (can also use drones for same purpose in war flying)
## Running the Test
- Initial access: when attacker exploits a vulnerability to gain access
- Privilege escalation: shift from initial access gained to more advanced privileges
- Pivoting or lateral movement: uses initial system compromise to gain access to other systems
- Persistence: installing backdoors and other mechanisms that'll allow them to regain access even if inital vulnerability is patched
## Cleaning Up
- Present results to management
- Clean up traces of their work (remove any tools used, remove persistence mechanisms)
- Provide target w/ details on vulnerabilites and how to improve their security posture

# Audits and Assessments
## Security Tests
- Security tests verify that a control is functioning properly
- Ex's: automated scans, tool-assisted pen tests, manual attempts
Side note: Responsible Disclosure Program allow security researchers to share info abt vulnerabilities privately w/ an organization
## Security Assessments
- Security assessments are comprehensive reviews of the security of a system, application, or other tested environment
- Review of the threat environment, current and future risks, value of targeted environement
- Boils down to a non-technical document presented to managment on results and recommendations for improving security of tested environment
## Security Audits
- Security audits are a formal examination to evaluate the effectiveness of controls, done by independent auditors
- Internal audits: performed by an organizations internal audit staff
- External audits: performed by outside auditing firm
- Independent Third-Party audits: same as external but someone outside your organization requests an audit of your organization
## Auditing Standards
- Standards provide description of control objectives that should be met
- Some common frameworks: COBIT, ISO 27001

# Vulnerability Life Cycle
## Vulnerability Identification
- Vulnerability scans
- Pen tests
- Reports from responsible disclosure or bug bounty programs
- Results of audits
## Vulnerability Analysis
- Confirming vulnerability exists and that its not a false positive
- Prioritizing and categorizing the vulnerability based on CVSS and CVE
- Supplementing external analysis w/ organization specific details
## Vulnerability Response and Remediation
- Apply a patch or other corrective measures to correct the vulnerability
- Network segmentation to isolate affected system
## Validation of Remediation
- Validate the vulnerability is no longer present
- Re-scan the system
## Reporting
- Communicate findings, actions taken, lessons learned to stakeholders in the organization
